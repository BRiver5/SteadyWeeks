# Steady Weeks — План реализации

> «Plan the week, not the streak.»
> Привычки с недельной квотой («бег 3×/нед»): приложение раскладывает квоты по
> дням, где ты реально их выполняешь, под дневной лимит времени, и честно
> говорит, что не влезает и что с этим сделать.

---

## 0. Архитектурные решения

- Полностью локальное: `expo-sqlite`, без бэкенда, без уведомлений.
- Разрешения: всё чувствительное заблокировано, включая `INTERNET` и
  `POST_NOTIFICATIONS`. Нужна только вибрация (`VIBRATE`, не блокируется).
- Тема всегда light, палитра — нефрит `#138652` на «меловом» `#F6F5F0`.
- Все записи в базу идут через один мьютекс (`src/data/repo.ts`), а
  `refresh()` стора — через очередь: параллельные транзакции expo-sqlite
  отклонял («NativeDatabase.execAsync has been rejected»).

| Разрешение | Зачем |
|---|---|
| `VIBRATE` | haptics на тапах/чек-инах/перетаскивании, выключается в Settings |
| `POST_NOTIFICATIONS` | не используется, заблокировано |

## 1. Движок (`src/lib`) — связка модулей

1. **`model.ts`** — накапливаемая бета-модель «запланировал на этот день недели →
   сделал». Ячейка (привычка × день) с забыванием 0.92 на наблюдение, частично
   объединена с уровнем привычки (сила 3), привычка — с общим априором 70%.
   Состояние хранится в `meta.model`, дообучается только на днях после
   `modelThrough`; `MODEL_VERSION` или правка прошлого дня → пересборка из журнала.
2. **`planner.ts`** — для каждой привычки все подмножества допустимых оставшихся
   дней (≤ 2⁷, с закрепами), у каждого точная вероятность закрыть квоту
   (пуассон-биномиальное) + вес прогресса; выбор по одному варианту под лимиты
   минут по дням — многомерный рюкзак с множественным выбором. Точное ветвление с
   границами: доминирование вариантов, граница по текущей загрузке, лагранжева
   граница (λ на минуты дня, субградиент в корне), порядок обхода по лагранжевой
   ценности, стартовый рекорд жадным + локальным поиском, допуск 0.002, бюджет
   узлов (флаг «proven / best found»).
3. **`changes.ts`** — общий язык изменений (лимит дня, занятый день, квота недели,
   разрешённый день, длина сессии, снятие закрепа) + `whatIf()` — сравнение
   до/после честным перепланированием.
4. **`conflicts.ts`** — недостижимая квота / зажатая лимитами привычка / переполненный
   закрепами день; выходы (одиночные и связки «место сразу на N днях») проверены
   перепланированием и ранжированы по выигрышу ожидаемых закрытых квот.
5. **`explain.ts`** — «почему эти дни»: разложение оценки дня (априор привычки vs
   своя история дня), вклад каждого дня в шанс квоты, причины невыбранных дней.
6. **`history.ts`** — журнал → наблюдения модели, недели, серии идеальных недель,
   калибровка прогнозов (Брайер + skill против плоского среднего), надёжность
   дней недели с порогом Уилсона.

Тесты: `src/lib/engine.test.ts` (в т.ч. сверка ветвления с полным перебором).

## 2. Модель данных

| Таблица | Поля |
|---|---|
| habits | id, name, target, minutes, days (маска Mon=бит 0), color, icon, created_at |
| completions | habit_id, day, planned — факт захода (≤ 1 в день) |
| planned | day, habit_id, p — снимок плана на день с прогнозом (прошлые не переписываются) |
| pins | habit_id, day — закрепы недели |
| overrides | week, habit_id, target — квота только на эту неделю |
| meta | capacity, haptics, busy (по неделям), model, modelVersion, modelThrough |

## 3. Экраны (6)

1. **Home** (Hero Card First) — hero-карточка с `WeekDial`, «Check in today» и
   «Open week plan» внутри; Today со свайпами (Done / pin to tomorrow); список
   привычек с `QuotaPips`, фильтром, long-press меню; липкие заголовки.
2. **Week plan** — `WeekBoard` (тап — объяснение, удержание — закреп,
   перетаскивание — перенос, тап по дню — занят), конфликты с выходами,
   «Why these days», `OddsBars` распределение закрытых квот.
3. **What if** — лимит дня / занятый день / квота / длина сессии, две колонки
   Now → If, по привычкам до/после и смена дней, Apply.
4. **Habit detail** (master-detail) — неделя и квота «только на эту неделю»,
   инлайн-правка имени/квоты/сессии/дней, `WeekdayOdds` с разложением, «почему»,
   тепловая карта 12 недель (тап — исправить запись).
5. **Stats** — 8 секций: кольцо ожидания + серии + сессии, `WeekBars`
   (интерактивно: неделя перестраивает экран), `CategoryRing` (интерактивно:
   привычка), квоты недели, heatmap, надёжность по дням с Уилсоном, калибровка,
   по плану vs сверх плана.
6. **Settings** — минуты на привычки по дням недели, вибрация, как считаются
   шансы, стереть данные.
